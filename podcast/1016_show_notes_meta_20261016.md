1016 MLSYS 论文简报：换模型，不只交接聊天记录

智能体做到一半换模型，接收者究竟需要什么？聊天记录让它知道前面发生了什么，计算缓存让它少做重复工作；这两种状态有关联，却不能相互替代。本期沿着“谁来接手、哪里返工、交接什么”三个问题，讨论有状态路由与跨模型计算复用。

一条看似简单的追问，可能接着前一轮未完成的修改。便宜模型的单价再低，也可能先付出重读长历史的成本。我们先讲三篇论文的具体机制，再集中讨论质量、成本和关键对照，不把阶段加速直接包装成完整任务的收益。

本期论文

Whose turn is it? Context-guided model routing for stateful agents
微软；arXiv 预印本。
https://arxiv.org/abs/2610.19292

路由发生在用户回合的起点：选中的模型负责本回合全部工具循环，下一次追问时再选择。运行时持续保留工作簿，历史记录请求、工具结果与错误，因此当前回合的难度取决于之前发生的事。

在 SheetCopilot 上，同一个路由器看到历史后，三组模型搭配的平均整段任务成功率从 25.0% 提高到 28.3%，便宜模型承担的回合比例相近。这个实验支持“历史帮助选对回合”，而不是“动态切换已经净省钱”。论文没有实测同一个首轮路由器选完就固定的对照；费用表也明确排除了 router 调用成本。

RaReCache: Bridging the Gap in Cross-Model KV Cache Reuse via Rank disagreement-based Selective Recomputation
南加州大学、加州大学欧文分校、英特尔研究院；arXiv 预印本。
https://arxiv.org/abs/2610.11358

先把已有发送端 KV 映射到接收端空间，再用校准子空间之外的能量，挑出值得接收模型亲自重算的位置。这里的 rank 是低秩子空间，不是多个模型的答案排名；重算位置仍关注完整上下文，不是删除其余历史。

Qwen3-0.6B→14B 在完整 GSM8K 测试中，纯映射准确率为 71.6%，重算 30% 位置后为 90.2%，原生接收模型完整预填充为 95.1%。这些数字来自同一个全量测试，不混用选择器诊断的 300 题结果。三成预算也不是通用质量保证：MMLU 上保留的原生准确率为 77.9%。校准分布、切换方向和服务负载，都会影响收益。

Accelerating Cross-Model LLM Inference via Attention Map Reuse（MapFlow）
北京大学；arXiv journal-reference 标注 SIGMOD 2027。
https://arxiv.org/abs/2610.14688

它共享“哪些 token 关注哪些 token”的注意力权重，而不是完整 KV。接收端先自行计算早期层，再混合发送端的注意力头，作用到自己产生的 V；稀疏分块缓存与融合算子避免物化完整的大地图。接收模型的内容表示、输出和前馈计算仍然存在。

论文报告预填充延迟相对完整预填充减少约 15%–20%，并与 FlexPrefill 等方法比较。在指定三模型顺序工作流中，端到端加速最多为 5.4%。两者是不同指标；长上下文测试也出现明显质量下降，不能说普遍无损。SIGMOD 信息采用 arXiv 标注，未独立核对官方录用目录。

集中讨论

本期评价：Whose turn is it 为“人上人”，RaReCache 与 MapFlow 为“顶级”。评价针对已展示的贡献，不代表任意场景都适用。后两种接续方案没有在同一协议下直接对打，不能据此宣布哪种表示全面胜出。

Handoff tax 至少涉及语义轨迹、环境状态、缓存计算和已消耗预算。缓存复用不能撤销错误修改，也不能自动修正前一位模型的推理。一个值得先做的对照是：同模型热缓存、同模型强制冷缓存，再在相同环境与预算下换模型。它帮助区分重算成本与其他交接影响，但简单相减不能自动识别每一种税。
