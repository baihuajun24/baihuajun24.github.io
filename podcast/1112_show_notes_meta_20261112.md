# 1112 MLSYS 特辑 · 只给一个目标，Agent 能把推理调多快？

## 评论

让通用编程 Agent 去优化推理系统本身，围着它搭的专用脚手架还值多少？两篇新论文给出看似相反的答案：一篇拆掉知识库和预设流程，只给一段目标，照样在一批 GPU 算子上超过专家维护的开源库；另一篇靠成本模型和隔离的验收，把投机解码的加速翻了一倍多。合起来的结论是：知识可以越给越少，尺子不能省。

## 本期重点

JustGoal（清华大学、面壁智能等）做了一个对照组：通用 Agent 只拿到目标和约束，自己搭编译、计时和正确性检查的闭环，验收由作者独立复测。在 NVIDIA B200 上，11 个算子、42 种输入形状里，进入比较的 10 个算子有 8 个快过开源库（几何平均 1.14 到 2.34 倍），9 个有公开专用 Agent 算子的里赢了 5 个；注意力前向算子只有开源库的 0.77 倍。同模型对照中，只优化单个形状时，只给目标是 1.18 倍，作者复现的专用框架是 1.12 倍；要求一次覆盖全部负载时，两者变成 0.71 倍和 0.97 倍。换三代模型，只给目标的做法从 0.51 倍涨到 1.18 倍。

SpecPilot（伯克利、普林斯顿、斯坦福、NVIDIA）让 Agent 逐个部署去调投机解码。它保留了三样东西：估算离上限还差多少的成本模型；一个 Agent 能调用但不能修改的控制器，负责成对计时和封存复测；以及把每个输出 token 送回原版引擎核对的检查，用来拦住靠改输出换速度的捷径。单请求下，相对逐 token 生成的加速从 4.46 倍提高到 10.87 倍，批处理从 1.94 倍到 3.93 倍，不需要重新训练。去掉成本模型的单 Agent 循环三轮后只有 1.34 倍，完整系统是 2.13 倍。

## 说明

两篇都是 arXiv 预印本。JustGoal 的专用框架是作者按公开材料复现的，成绩低于原团队发布的算子；实验只在一种显卡上，每个形状只跑一个会话。SpecPilot 的批处理对比对象只有调优过的原版系统；十三轮循环共用 530 个显卡小时。节目中的评价是主持人的解读。本期音频由 AI 语音合成。
