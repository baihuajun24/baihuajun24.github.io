0812 隐状态路由特辑 · 模型知道自己会不会做错吗？

Audio: 10:20

评论
路由的信号该从哪里来？上一期讲的是模型外面——把 query 编码成向量，看它像不像见过的难题。这一期换轴：信号取自模型内部的隐状态——模型在预填充阶段就已经算好的那份表示，不生成任何 token，判断在开口之前就做完。四篇里有一组正面对撞——牛津说模型自己的激活里就写着它会不会做错，英伟达说外来的编码模型读你比你读自己更准；第三篇把它落进端边云三层系统；第四篇则指出，大家追的那块路由收益，有一到三成六其实是测量噪声。串到最后有一句扎心的共同点：没有一篇把路由器自己那一次前向算进成本里。

本期重点
先把这件事说清楚：你把提示喂进模型，它在吐出第一个 token 之前已经把整段提示完整过了一遍——这个阶段叫预填充，每层都会算出隐状态。这份表示反正都要算——那它里面是不是已经写着"这道题我会不会做错"？

第一篇 LLMs Encode Their Failures（牛津大学 / 伦敦大学学院）说是。做法朴素得过分：在模型自己的残差流上取指令结尾单个 token 位置、某一层的隐状态，训一个线性探针预测它答不答得对。不生成 token、不训额外编码器、不动权重。它拿五个候选做效用路由，其中同一份权重的三档推理预算被当成三个不同候选——所以路由不只是选模型，也是选思考预算。探针在推理型模型上判别力做到零点七以上、部分零点八以上。最值得称道的是它报了一个对自己不利的发现：目标模型推理预算越高，探针越不准，单调下降，哪怕模型准确率在上升。边界：只用单层单位置、只在数学和代码上验证、模型不超过两百亿，且闭源模型拿不到激活——那恰是现实里最常见的路由场景。评级夯。

第二篇是转折。LLM Router: Prefill is All You Need（英伟达）同意信号就在这份隐状态里，但把出信号的模型和被预测的模型拆开，用一个与目标无关的编码模型去读同一个 query，并报出反直觉结果：外来编码模型一致地比目标自己的隐状态更准地预测该目标会不会做对。好处很实际——闭源模型拿不到激活，但可以用开源模型读 query 给闭源候选打分。三个候选池、一千三百多组配置、基线含多种主流语义路由器。代价是这期最该记住的一句：表现最好的编码模型是一千两百亿参数级别，而全文没有报这次编码的时延、算力或首 token 影响；更麻烦的是结构问题——编码模型不是目标模型，所以为路由算出的那份缓存用不上，选中的模型还得从头再算。它自承为纯域内评测，无跨域、无加新模型不重训的测试。评级人上人。

第三篇 ConsRoute（哈尔滨工业大学）把这套东西落进端边云三层。信号取自端侧一点七B的小模型：在 query 后追加一句固定提示（大意是"小模型和大模型的回答一致性是"），取最后一层该结尾位置的隐状态，喂进五百万参数的小头回归出一致性分数，高就本地答、低就上送。它把"我会不会做对"换成了"我和大模型答得一样吗"，监督更好造。结果是拿到云端准确率九成五以上，时延为云端六到六成五，成本约七成；还按聚类给不同查询配不同阈值、用贝叶斯优化调参。它是四篇里唯一明确提出复用 KV 的——若留在端侧，预填充阶段的缓存可直接接着解码；但这一条是断言，全文没有测量也没有消融，且一旦升级到边或云，端侧这一次前向是纯浪费、同样未被量化。只用最后一层、无层扫描，网络条件为模拟。评级人上人。

第四篇 How Much of the Routing Gap Is Real?（阳明交通大学 / Krixvon AI）不训任何路由器，去审计大家用的那把尺子。通行做法拿"完美路由"当上界，可这个上界是从每题每模型只采样一次的结果里取最大值——单次采样的随机性会系统性抬高它。他们把十一个模型跨八个谱系重新生成、每格采三十次对齐随机种子，把差距精确拆成可回收部分与单次采样噪声地板，三个基准上噪声占差距的一成二、三成六、一成三；并证明任何"看完信号一次性提交"的路由器都封不掉这块。评级夯：它不刷点，它换了分母。

串下来是一个干净的三角：同一个问题——谁最清楚这题该给谁做——三篇给了三个答案：模型自己、一个与它无关的外人、还是楼下那个最小的模型。而共同的空白是，没有一篇把路由器自己那一次前向算进成本。
