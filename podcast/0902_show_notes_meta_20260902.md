0902 MLSYS 论文简报：agent 把缓存这本账重记了

Audio: 11:18

评论
停更三周，回来第一期做一个主题：当请求从人打字变成 agent 自动发起，KV 缓存这本账被重记了。三篇论文正好落在三个尺度上——集群怎么路由、单机留什么、以及缓存的单位到底该是什么。最反直觉的一条来自生产数据：当全局缓存层配足之后，一个完全不看缓存、纯按负载派发的调度器，吞吐只比最强基线低 7%，四种策略的整体复用率几乎一样，差别只在命中来自哪一层。也就是说，全局层已经把「复用」和「请求落在哪」解耦了，而调度器还在为复用牺牲均衡。到了第三篇，连「前缀」这个前提本身都被拆掉：可重排的工具集合根本不构成前缀。

本期重点

集群这一层：路由。SMetric（上海交大 IPADS / 阿里）先摆生产数据：两条真实商用编码智能体的 trace 里，92.9% 的请求是 agent 自动发出的而不是人在打字；缓存可复用比例超过 80%，而聊天负载只有 54–62%。目标也随之改变——agent 只在拿到完整回复后才行动，所以集群总吞吐成了第一目标。于是所有调度器都在抢缓存亲和，代价是负载不均衡：生产调度器 2.7 倍、学术基线 3.0 倍。这篇最有价值的观察是反直觉的：全局缓存层配满时，完全不看缓存的纯负载均衡调度器吞吐只低 7%，四种策略整体复用率都在 73–75%，差别只在命中层级（本地命中 58% vs 6%）。另一张图说明了「会话钉死」：缓存亲和策略下 96.6% 的后续请求回到首轮实例，纯负载均衡下只有 4.0% —— 一个会话的命运在第一个请求落地时就定了。所以方案只有一句：只把每个会话的首个请求纯按负载打散，后续照常走缓存亲和；而「这是第几轮」这个信号是白嫖的，因为接口无状态、每个请求都带完整历史，数一数消息条数即可，路由器本身完全无状态（他们刻意否决了 session→instance 映射表，理由是会话永不显式结束、这张表得一直长还得做 GC）。效果：同机部署吞吐高 10–16%，首字时延中位数 1.1 秒。评级夯。但账要算清楚：宣传的「预填充吞吐 +2~34%」，2% 那个低端恰恰是全局层配满的点——全局层越充裕它优势越小；完全没有全局存储时它和生产调度器差在 1% 以内，这套方案本质上要先有两层缓存的基建。增益还只集中在饱和拐点附近的窄区间（1.0× 负载差 1%、1.5× 高 15%、1.75× 只高 4%）。trace 未公开，两条只回放了一条，采集窗口仅两小时，测试床 32 张卡对面是上千卡的生产集群。

单机这一层：留存。TOPAS（中科大 / 合工大）把同一个矛盾下沉到一张卡：agent 的长 system prompt 前缀常驻能省 prefill，但它占走的显存就是留给并发批处理和解码的显存。动机实验朴素也够狠——同一批请求、同样预算，只把服务顺序从两个 agent 交替改成按 agent 分组，平均批大小从 4.7 涨到 9.3，总耗时从 2086 秒掉到 1145 秒。论文里还有一张手算的图：追进度的策略平均完成时间 21.5，而攒同前缀请求、摊薄装载费的策略反而是 24 —— 两种看起来都对的直觉互相打脸。它的做法是不再逐个请求排序，而是枚举「这一步之后留哪几段前缀、同时能跑哪一批请求」这个联合状态并按秒打分；最值得说的是收益的定义——不按请求自身的服务时间算，而按这个请求做完之后任务最长剩余路径能缩短多少，于是推进一条非瓶颈分支不会被错记成进度。数字：合成工作流 mean/p99 完成时间降 39.8%/49.4%，真实的两个 MetaGPT 工作流分别是 22.0% 和 9.8%。评级人上人。口径要说清楚：39.8% 是合成负载，用的是固定长度 query 和固定生成长度，等于把「路径长度可预测」这个最有利条件给足了，真实流水线上是个位数。证据也偏薄：单张 A100、单实例，到达序列只采样一次、无重复实验、无方差——p99 这种尾指标在单次实验下尤其不稳。前提也强：它假设所有任务遵循同一个已知的工作流图，而「最长剩余路径」正是靠这张图算出来的。

缓存单元这一层：前缀这个前提本身。ReCache（上海交大 / 宁波东方理工 / 西安交大）盯的是工具与技能的 schema：agent 按任务检索工具，同一个工具反复出现，但每次的组合不同、顺序也不同；而前缀缓存要求复用内容构成完全相同的前缀，所以只要换掉一个工具、或同一批换个排列顺序，后面所有工具的 KV 就全部作废。它的改法是抹掉跨资源注意力、把每个工具内部的位置索引归零重排，而周围上下文保留原位置——这样同一个工具无论排第几、和谁一起被检索，KV 都是同一份，可以离线单独构造、单独复用。消融里有全篇最刺眼的数字：每个工具只留最后一个 token，调用分数掉到 14.8、幻觉率 76%，模型基本在瞎编工具名；仅仅把工具名加回去，幻觉率就相对下降 97.63%。另一个对照更好玩：在工具名和参数名的基础上再加「这个工具是干嘛的」那段描述，分数只从 67.7 动到 67.9，而加「这个参数该怎么填」直接到 72.8 —— 模型要的是约束，不是散文。数字上，只做那一步注意力改造，见过的工具上 82.3 对稠密基线 82.4 基本持平、首字时延快 3.655 倍，完整版显存降 92.43%。评级人上人，但三笔账都不轻：其一它不是免训练的，需要全参数微调，作者在局限性里自承冻结模型留作未来工作；其二「基本持平」那个 82.3 只是单独一项且只在训练见过的工具上成立，完整版在见过的工具上掉 2.1 分，而在完全没见过的工具上是 60.8 对 66.3、掉了 5.5 分——而「没见过的新工具」恰恰是它想解决的场景；其三表里没有跑任何一个真正的缓存复用基线，前缀缓存本身以及相关工作点名的那几套免训练方案全都只在文献综述里出现过。3.655 倍那个首字时延，定义上也排除了离线缓存构造，等于假设 100% 命中。

收尾。三篇在三个尺度上打同一场仗。共同点是 agent 同时拆掉了两个前提：一个是「复用和请求落在哪儿绑定」——全局缓存层已经把它解耦了；另一个是「复用是前缀形状的」——可重排的工具集合根本不是前缀。所以下次看到「我们做了 KV 缓存优化」，可以先问一句：你优化的是命中率，还是命中来自哪一层？
